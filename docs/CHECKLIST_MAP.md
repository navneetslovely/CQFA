# Where each reproducibility item is evidenced

The reproducibility checklist submitted with the paper answers a set of
questions about this code and data. This document points to the evidence for
each one.

---

## Theoretical contributions

| item | evidence |
|---|---|
| Assumptions and restrictions stated | Each proposition carries its hypotheses; the library encodes them, for example the linear-independence condition in `src/cqfa/dynamical_lie_algebra.py` and the observable condition `P_g(M) > 0` in `src/cqfa/certificate.py` |
| Claims demonstrated empirically | `src/cqfa/verify.py` re-derives the invariance identities; `python scripts/smoke_test.py` runs them |
| Code used to eliminate or disprove claims | `experiments/exploratory/` retains five studies that report no result in either document, with its own README |

## Dataset usage

| item | evidence |
|---|---|
| Motivation for the selected data | `src/datasets/DATA_STATEMENT.md` documents every source and why it is used |
| Novel data included | `src/datasets/genomics_reverse_complement.py` is a deterministic generator; the dataset is reproduced exactly from fixed seeds rather than shipped as a static file |
| Licence permitting research use | `LICENSE` |
| Data drawn from the literature is cited | The discrete-log concept class and the symmetry-protected order parameter are cited in the module docstrings of `experiments/discrete_log/` and `experiments/spt_measurement_cost/` |

## Computational experiments

| item | evidence |
|---|---|
| Number and range of values tried, and the selection criterion | Classical baseline grids and the selection rule are in `analysis/build_tables.py` and the supplementary tables; the search itself is `experiments/discrete_log/dlp_baselines_tuned.py` |
| Pre-processing code | `src/datasets/` |
| All source code for conducting and analysing the experiments | `src/`, `experiments/`, `analysis/`, `figures/` |
| Code will be publicly available under a research-use licence | `LICENSE` |
| Seed methodology | All randomness flows through explicit seed arguments; the data-seed convention is `1000 + seed`; each run records its seed list in `config.json`. See `docs/ENVIRONMENT.md` |
| Computing infrastructure | `docs/ENVIRONMENT.md` — exact CPU, memory, operating system and pinned versions for every library |
| Evaluation metrics | Defined in `src/cqfa/train.py` and `experiments/multitask_benchmark/metrics.py`; the benchmark records accuracy, balanced accuracy, Matthews correlation and area under the precision-recall curve with bootstrap intervals |
| Number of runs per reported result | Seed lists are recorded per run in `runs/*/config.json`; aggregate counts appear in the `n_seeds` column of `results/aggregated/benchmark_master.csv` |
| Variation and confidence | Every aggregated CSV carries standard deviations and bootstrap confidence intervals alongside the mean |
| Statistical tests | `experiments/readout_basis/u1_abstract_evidence.py` computes the Pearson and Spearman correlations and paired tests; bootstrap intervals are computed in `src/cqfa/train.py` |
| Final hyperparameters | Shared settings are in the supplementary tables, generated by `analysis/build_tables.py`. The benchmark sweep varies its configuration per cell, so each run writes a `config.json` recording the representation, model, task, seed list, train and test sizes, epochs, learning rate, depth and teacher seed. There are 208 such files under `runs/`. The classical reverse-complement baseline is not run through that harness; its parameters are fixed in `src/datasets/rc_symmetric_baseline.py` |

## Integrity

`MANIFEST.sha256` carries a SHA-256 hash of every file in the archive.

```bash
python scripts/verify_manifest.py
```

`docs/CLAIMS_TO_RESULTS.md` maps every reported number to the file it comes
from and the command that regenerates that file.
